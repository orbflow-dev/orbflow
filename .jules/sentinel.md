## 2025-02-14 - Fix Path Traversal Bypass via `unwrap_or_else` in Path Canonicalization
**Vulnerability:** A path traversal check in the plugin uninstallation endpoint (`crates/orbflow-httpapi/src/handlers.rs`) was bypassed when path canonicalization failed. It used `.unwrap_or_else(|_| dir_check.clone())`, falling back to the uncanonicalized path if the directory didn't exist or lacked permissions. Since `Path::starts_with` performs lexical checks (meaning `/base/../target` starts with `/base`), an attacker could craft a path to delete arbitrary directories if they created the directory right after the existence check (TOCTOU).
**Learning:** Never use "fail-open" defaults (like `unwrap_or_else` falling back to the input) for security-critical validation like path canonicalization. A failure to canonicalize means the system cannot safely assert the path's true location.
**Prevention:** If canonicalization fails, the operation must fail securely (e.g., return an error immediately) rather than proceeding with potentially unsafe input.

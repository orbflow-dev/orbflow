## 2024-05-24 - [SSRF bypass via TOCTOU / DNS Rebinding]
**Vulnerability:** The `CredentialProxy` validated URLs for SSRF protection by resolving the hostname and checking the IPs. However, it then passed the URL to a standard `reqwest::Client`. `reqwest` performs its own DNS resolution at connection time. This gap allows an attacker to bypass the blocklist using DNS rebinding (serving a benign IP on the first resolution, and a malicious internal IP like AWS metadata on the second).
**Learning:** URL host validation logic must be strongly coupled to the actual HTTP client connection lifecycle to avoid Time-Of-Check to Time-Of-Use (TOCTOU) issues.
**Prevention:** Implement SSRF validation directly within a custom DNS resolver (`reqwest::dns::Resolve`) and configure the HTTP client to use it, guaranteeing that the IP validated is the exact IP connected to. Additionally, disable HTTP redirects to prevent bypasses via 301/302 redirects to internal resources.

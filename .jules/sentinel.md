## 2024-08-30 - Path Traversal Bypass via Canonicalization Fail-Open
**Vulnerability:** A path traversal vulnerability existed in the `uninstall_plugin` handler due to a "fail-open" pattern on path canonicalization. If `fs::canonicalize` failed (e.g., because the directory was deleted between check and execution, or due to a permissions issue), the code used `unwrap_or_else` to silently fall back to an uncanonicalized string. The subsequent `starts_with` check compared path components without resolving `../`, allowing a path like `/plugins/../../target` to bypass the directory constraint.
**Learning:** In Rust, `Path::starts_with` only compares path segments lexically. It does not resolve `.` or `..` segments. Therefore, it is absolutely critical that both the base and target paths are successfully canonicalized before comparison. Using `unwrap_or_else` to provide an uncanonicalized fallback path renders the security check completely ineffective.
**Prevention:** Always "fail closed" on canonicalization errors when validating directory constraints. Use `map_err` to propagate the error rather than falling back to an uncanonicalized path.

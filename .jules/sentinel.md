## 2024-11-04 - Credential Proxy SSRF via DNS Rebinding and Redirect Leakage
**Vulnerability:** The `CredentialProxy` in `orbflow-worker` resolves hostnames to validate them against SSRF blocklists using `tokio::net::lookup_host`, but then hands the original URL to a default `reqwest::Client`. This creates a Time-of-Check to Time-of-Use (TOCTOU) vulnerability where the DNS can rebind to a private IP (e.g. `127.0.0.1` or `169.254.169.254`) after the check but before the actual HTTP request. Additionally, the proxy automatically follows redirects by default, meaning a malicious server could return a `3xx` redirect to a different domain, causing the proxy to leak injected credentials to an untrusted third party.
**Learning:** SSRF defenses that validate hostnames asynchronously before passing them to a high-level HTTP client are fundamentally flawed unless the HTTP client is forced to use the exact same IP address (or the client itself validates IPs upon resolution).
**Prevention:** Implement a custom `reqwest::dns::Resolve` that performs the IP blocklist check synchronously during the actual connection phase, and inject it into the `reqwest::Client`. Explicitly disable redirects (`reqwest::redirect::Policy::none()`) when acting as a credential-injecting proxy.

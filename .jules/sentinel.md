## 2026-06-13 - [Sentinel] SSRF in `CredentialProxy::new`
**Vulnerability:** The `reqwest::Client` in `CredentialProxy` was initialized without a custom DNS resolver and with default redirect behavior. This made it vulnerable to Server-Side Request Forgery (SSRF) and Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding attacks.
**Learning:** `reqwest` clients require custom DNS resolvers when used to validate and execute requests to untrusted or potentially malicious URLs. By default, `reqwest` will follow redirects and resolve DNS without restricting internal IPs, allowing attackers to bypass pre-flight URL validation checks by returning a public IP initially and a private IP upon a subsequent resolution or redirect.
**Prevention:** To prevent SSRF/TOCTOU, implement a custom `reqwest::dns::Resolve` struct that checks each resolved `SocketAddr` against `is_private_ip()`, configure the client with `.dns_resolver()`, and disable redirects via `.redirect(reqwest::redirect::Policy::none())` when proxying user-controlled requests. Initialize securely and use `.expect()` to fail closed if building the client fails.

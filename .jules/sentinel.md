## 2025-05-17 - Fix SSRF Vulnerability in Credential Proxy URL Validation
**Vulnerability:** The credential proxy in `orbflow-worker` used insecure string manipulation (`starts_with`, `contains`) to validate proxy URLs against a blocklist of cloud metadata IPs and to enforce the HTTPS/localhost scheme requirement.
**Learning:** This approach is vulnerable to SSRF bypasses via IP obfuscation (e.g., using integer IPs like `2852039166` instead of `169.254.169.254`) and prefix hijacking (`http://127.0.0.1.attacker.com`). Robust URL parsing using `url::Url::parse` is required to accurately extract the scheme, host, and IP. Additionally, while exact matching is safer for IP validation, maintaining a fallback substring check (`url.contains`) acts as a crucial defense-in-depth measure to catch domain-based IP resolution bypasses (like `.nip.io`) or embedded IPv4-mapped IPv6 strings.
**Prevention:** Always use a robust URL parsing library (`url::Url`) to extract and validate URL components securely when implementing SSRF protections. Supplement parsing-based checks with string-based fallback checks for comprehensive defense-in-depth.

## 2024-07-12 - [Path Traversal in Plugin Uninstallation]
**Vulnerability:** A path traversal vulnerability existed in the plugin uninstallation routine (`crates/orbflow-httpapi/src/handlers.rs`). The code checked if a directory was within the allowed plugins directory using `std::path::Path::starts_with`. However, if `std::fs::canonicalize` failed (e.g., if the file didn't exist or due to permissions), it fell back to using the uncanonicalized path via `.unwrap_or_else()`. Since `starts_with` checks path components, an uncanonicalized malicious path like `/plugins_base/../../../etc/passwd` would falsely evaluate as starting with `/plugins_base`, bypassing the security check.
**Learning:** Fallback mechanisms (fail-open) in security boundary checks (like path canonicalization) are highly dangerous because they can silently allow invalid or malicious inputs to bypass the intended validation logic.
**Prevention:** Always "fail closed" for security checks. If a prerequisite for a security check (like canonicalizing a path to resolve `..` components) fails, the entire operation must fail securely and immediately return an error, rather than falling back to an unverified state.
